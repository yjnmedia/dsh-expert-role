# 插件的最小结构

## 一个能装上的插件至少有这些

```
my-plugin/
├── package.json        # name / version / main / dsh 字段 / cordis 配置
├── index.js            # 导出 apply(ctx) 与可选 Config
├── cordis.patch.yml    # 告诉宿主这个包往哪个插件目录挂
└── README.md
```

`package.json` 里几个关键键：

```json
{
  "name": "dsh-my-plugin",
  "version": "0.1.0",
  "type": "module",
  "main": "index.js",
  "dsh": { "kind": "plugin" },
  "engines": { "dsh": ">=0.2.0" },
  "files": ["index.js", "cordis.patch.yml", "README.md"]
}
```

`files` 决定 npm 包里带什么；带多了会把资料、模型一起发出去。

## index.js 的骨架

```js
export const name = 'dsh-my-plugin'
export const inject = ['webServer', 'tools']   // 必须有才启动；可选服务用 ctx.get

export function apply(ctx, config = {}) {
  ctx.effect(() => {
    // 挂载副作用；返回的函数在卸载时执行
    return () => {}
  }, 'my-plugin.effect')
}
```

## 三类入口

| 入口 | 注册方式 | 用户看到的位置 |
|---|---|---|
| 面板 | `sidebar.panellist` + `main` 组件 | 左侧栏一个图标，点开是面板 |
| 工具 | `ctx.tools.register(name, schema, handler)` | 模型可调用 |
| 技能 | 提供 skill provider，指向 `SKILL.md` | 技能目录 |

## 本地联调

插件用 `link:` 装进 profile 后，改源码会被宿主热重载（整插件卸载重载、`apply` 重跑）。所以：
- `apply` 必须可重复执行，别在里面做一次性初始化；
- 副作用用 `ctx.effect` 包起来，卸载时能收回。
