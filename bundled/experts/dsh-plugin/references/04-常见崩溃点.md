# 常见崩溃点

## 1. 插件一装，宿主进安全模式

症状：面板全空、已装插件被清掉。

最常见的原因：技能 provider 返回的对象缺 `name`（写成了 `id`），宿主报
`skill provider "undefined" returned skill …`。

恢复：清掉 profile 里该插件，用备份的 `package.json` 还原。

## 2. 插件显示 pending、点了没反应

- `inject` 里写了宿主没有的服务 → 去掉，改 `ctx.get`；
- `engines.dsh` 要求高于当前版本 → 改要求或升级宿主；
- 面板路由 404 → 检查 `apply` 里确实注册了路由，且路径前缀与客户端请求一致。

## 3. 路径错位：本地能用、装上就坏

用 `process.cwd()` 拼插件内路径，在 `link:` 安装下 cwd 是宿主目录，必然错。

```js
// 对：按模块位置解析
const root = fileURLToPath(new URL('.', import.meta.url))
```

## 4. 面板渲染整体错位

面板里状态是**按顺序**取的（`useState` 的调用位置即序号）。在中间插一个状态，后面所有状态整体后移：
渲染不报错，但值全串了。

对策：状态定义写成一个具名表 + 一条测试，比对源码里的顺序；别靠注释提醒。

## 5. 事件收不到 / 收了一半

- 事件名写错（`session/event` 不是 `session:event`）；
- 用了 `ctx.on` 但没在卸载时 `off`，热重载后重复注册、一条记两遍；
- 取字段取错（`agent/turn-stopping` 的 payload 是 `{ agent }`）。

## 6. 热重载后样式/缓存不更新

`<style>` 只在首次注入的话，重载后还是旧样式。每次 `apply` 都要覆盖写入，而不是「有就跳过」。

## 排查顺序

1. 拿报错原文，不猜；
2. 确认宿主版本与插件版本；
3. 用最小复现（只留出问题的那一个入口）；
4. 修完补一条测试，把这次错误变成机器能检查的东西。
