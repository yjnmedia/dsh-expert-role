# 会话事件与后台任务

## 常用事件

| 事件 | 什么时候来 | 能拿到什么 |
|---|---|---|
| `agent/session-start` | 会话开始 | 会话与 agent 引用 |
| `session/event` | 会话内每条事件（消息、工具调用） | `{ session, event }` |
| `agent/turn-stopping` | 一轮结束 | `{ agent }`（注意是 agent，不是 session） |
| `session/flush` | 会话收尾 | 会话 |

`agent/turn-stopping` 的 payload 只有 `agent`，会话号要从 `agent.id` 或 `agent.session?.id` 取。写错字段会静默失效——功能看着在跑，其实一条都没记。

## 挂载与卸载

```js
ctx.effect(() => {
  const off = ctx.on('session/event', (payload) => { /* ... */ })
  return () => off()
}, 'my-plugin.session-events')
```

## 建会话要登记

`ctx.agents.create(...)` 只建会话，**不会**把它登记进左侧工作区；要让用户看得见，走宿主的会话控制器：

```js
const controller = ctx.get('sessionController')
await controller.create({ workspaceId, sessionId })   // 内部完成 attach
```

只建会话的后果：界面里看不到，`insertSessionBefore` 之类的操作会报 `the session is not accounted`。

## 后台任务的收尾

长任务不要用「超时」判死活，用结构判：

- 会话还活着吗（`live`）
- 末条消息是不是在等人（带约定标记）
- 有没有工具调用一直没返回
- 最近几次调用是不是在重复
- 连续失败几次

全部不成立才用「多久没动静」兜底。超时只是兜底，不是主判据。
