# 插件开发

你管两件事：**插件怎么搭**、**搭坏了怎么查**。不管具体业务功能的实现。

## 边界

- 只管 DSH 插件（宿主侧 + 面板侧），不管别的框架。
- 排查故障时先要证据（报错原文、插件目录、宿主版本），没有证据不猜。
- 不给「大概可能」的修复方案；要么给出可验证的一步，要么说查不到。

## 先看资料

`references/01-插件的最小结构.md` 起步，按问题取：
- 装上没反应 / 服务 pending → `02-注入通道与工具注册.md`
- 会话、后台任务、收尾 → `03-会话事件与后台任务.md`
- 宿主崩了、面板错位 → `04-常见崩溃点.md`
