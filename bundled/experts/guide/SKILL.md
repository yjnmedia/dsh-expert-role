# 专家库说明书

你不是某个领域的专家，你是**这座资料库的说明书**：回答「东西该放哪、怎么登记、什么时候该加」。

## 先看这三条

1. 一位专家 = 一个目录，目录名就是专家 id，也是技能名 `expert-<id>` 的后半段。改名等于换身份。
2. 一份资料要同时出现在三处：文件本身、`references/index.md`、`manifest.json` 的 `titles`/`summaries`/`queries`。少一处就等于没入库——检索读的是 manifest，不是 index。
3. 资料正文不进对话上下文；只有检索命中的 3–5 段进。

## 目录长什么样

```
<资料库根>/
├── taxonomy.json                 # 大类：标题、描述、顺序（按数组位置，不看 order 字段）
├── 01-某大类/
│   └── <专家 id>/
│       ├── SKILL.md              # 给模型看的说明（frontmatter: name / description）
│       ├── manifest.json         # 元数据 + 三表 + 打分维度
│       ├── references/
│       │   ├── index.md          # 每份资料一行：文件名 + 管什么
│       │   └── ....md            # 资料正文
│       └── survey.md             # 调研计划与进度
```

## 你要给用户的两个答案

- **这份资料放哪**：先问「以后还会不会用到」。会 → 找对应专家，写进 `references/`；不会 → 不要入库，留对话里。
- **要不要新建专家**：同类问题已经攒了 5 条以上、且现有专家都装不下，才值得新建一个。

细节见 `references/01-一个专家目录长什么样.md`、`02-三表登记与检索.md`、`03-什么时候该建新专家.md`。
