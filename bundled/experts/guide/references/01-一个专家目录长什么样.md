# 一个专家目录长什么样

## 四个文件

| 文件 | 作用 | 可以缺吗 |
|---|---|---|
| `SKILL.md` | 给模型读的说明，frontmatter 至少 `name`、`description`；正文写边界与用法 | 不行，缺了就不算技能 |
| `manifest.json` | 元数据 + 三表 + 打分维度 | 不行，检索靠它 |
| `references/` | 资料正文，一份一个文件或一个子目录 | 可以空着，但空着就没有可检索内容 |
| `survey.md` | 调研计划、步骤、进度 | 可以空着 |

## manifest.json 里常用的键

```json
{
  "id": "reading",
  "title": "阅读器专家",
  "description": "一句话说清管什么",
  "level1": "终端与场景",
  "mode": "serial",
  "status": "ready",
  "whenToUse": "用户要改阅读器时",
  "triggerWords": ["阅读器", "分页"],
  "topics": [
    { "id": "layout", "title": "排版", "whenToUse": "涉及字号、行高时", "files": ["references/01-排版.md"] }
  ],
  "titles":    { "references/01-排版.md": "正文行高与字号怎么配" },
  "summaries": { "正文行高与字号怎么配": "14px 正文配 22px 行高；中文每行 28–34 字。" },
  "queries":   { "正文行高与字号怎么配": ["行高", "字号", "正文排版"] }
}
```

`titles` 的键是**相对专家目录**的路径，值是一句人话标题；`summaries` 与 `queries` 的键是那个标题。

## 命名的三个约定

- 目录名/专家 id 用小写连字符，别用中文，别改已发布的 id。
- 资料文件名带日期：`typography-scale_20261120.md`，同名不同日期不会被覆盖。
- 一份资料只留一处；同一份内容复制到两个专家，之后一定会不一致。

## 检查

搭完跑一次体检（仓库里有 `scripts/expertctl.mjs`）：目录名与 manifest.id 一致、资料两表都在、大类与磁盘对得上。
