# 专家角色（dsh-expert-role）

**中文** · [English](README.en.md)

[![license](https://img.shields.io/badge/license-MIT-blue)](LICENSE)
[![version](https://img.shields.io/github/package-json/v/yjnmedia/dsh-expert-role)](package.json)
[![dsh](https://img.shields.io/badge/DSH-%E2%89%A50.2-4B5563)](https://github.com/deepseek-ai/deepseek-harness)

**把领域知识做成随用随取的专家库：一个目录一位专家，模型按需加载，每次读取都留痕。**

模型的知识不覆盖新领域（AI 生图、短剧、某个内部工具），资料又散在几十个文件夹里。这个插件把「一个领域的资料 + 调研过程」收成一位**专家**，注册成技能；模型平时只看到一行简介，真正需要时再读正文和引用文件。读过什么、什么时候读的，都写进调用记录。

## 三步上手

1. 装插件、重启 DSH，左侧菜单多出「专家库」。
2. 在对话里说「帮我建一个 AI 生图专家，把 `D:\调研\生图` 这些资料整理进去」——模型会建骨架、把资料搬进来、登记成技能。
3. 需要时直接问；模型按「调用方式」（默认：你点名才查）决定要不要加载这位专家。界面可在「设置 → 界面语言」里切成 English。

插件只做三件事：**把资料变成可加载的技能**、**把调研过程写进同一个目录**、**把每次读取记下来**。

## 资料分类（随仓库发布的默认骨架）

资料按八类归位，**框架随仓库发布**，空着的类目先留位、不建空壳专家：

| 大类 | 放什么 |
|---|---|
| 平台与运行时 | 操作系统、容器、运行时、部署载体 |
| 工程与交付 | 构建、测试、CI、插件与技能工程 |
| 界面与体验 | 视觉、排版、交互、信息架构、无障碍 |
| 内容生产 | 生图、短剧、文案、素材 |
| 人工智能 | 模型接入、RAG、Agent 编排、评测、知识组织 |
| 终端与场景 | 阅读器、播放器、游戏自动化等具体终端 |
| 业务与运营 | 商品、库存、进销存等业务域 |
| 专业技术 | 兜底类：暂不属于以上各类，或管专家库自身 |

- 默认表在插件根目录 `taxonomy.json`；资料库根目录放同名文件则以本地为准（便于你自己调整大类名或顺序）。
- 专家用 `manifest.json` 的 `level1` 声明属于哪一类；未声明的自动并进「专业技术」。
- 专家目录可以平铺在库根，也可以放进 `01-平台与运行/` 这类大类目录，两种都能扫到。
- 面板「概况」页有「资料分类」一块，空类目显示「待填」——不是缺功能，是等你往里放专家。

## 2.0 更新公告（2026-11-18）

这一版换了「怎么找资料」：以前是先猜该问哪位专家、再进那个库找；现在直接在所有资料里找最像的几份，专家退成标签。

- **按资料检索**：一句话进来，直接返回最像的 3–5 份资料（带相似度），不再先选专家；专家只用来标注这份资料归谁管。
- **说不准就说**：最高相似度低于 0.5，第一句直接写「这几份都不太像，可能库里没有」；前两名分差小于 0.01 时提示「两份都读再判断」。
- **离线向量**：本地小模型算相似度，不出网、不花额度；没有模型文件时自动退回关键词检索，仍能用。
- **源码分级**：自有项目源码记 S、复用过的第三方 A、只收集没用过 B、文档调研 C、推测 D；新工具可以直接列出某位专家登记了哪些源码。
- **缺口自己判**：库里没有的问题按主题归并，插件自己判「该转给别人 / 该回收已有资料 / 才需要去查」；只有「去查」要花额度时才问你。

### 第一次使用：准备检索模型（约 95MB，只需一次）

模型文件不进仓库（太大）。在插件目录执行：

```bash
mkdir -p models/bge-small-zh
curl -L -o models/bge-small-zh/model-fp32.onnx \
  https://hf-mirror.com/BAAI/bge-small-zh-v1.5/resolve/main/onnx/model.onnx
curl -L -o models/bge-small-zh/vocab.txt \
  https://hf-mirror.com/BAAI/bge-small-zh-v1.5/resolve/main/vocab.txt
```

放好后重启一次 DSH。没放也能用，只是退回按关键词匹配，命中率会低一些。

## 安装

```bash
git clone https://github.com/yjnmedia/dsh-expert-role.git
cd dsh-expert-role
dsh plugin --profile desktop add .
```

Windows（PowerShell）同样三条命令，最后一行一样。

装完重启 DSH，左侧菜单的入口列表里会多一项「专家库」。它插在菜单已有入口之间，具体位置取决于你还装了哪些插件——认名字即可。插件针对 DSH 0.2 系列开发。

## 先指一个专家库目录

专家库就是一个普通文件夹，插件从环境变量 `DSH_EXPERT_ROOT` 读它的位置：

```powershell
# Windows，永久生效
setx DSH_EXPERT_ROOT "D:\AIExperts"
```

```bash
# macOS / Linux
export DSH_EXPERT_ROOT="$HOME/AIExperts"
```

不设的话，默认用用户主目录下的 `AIExperts`（Windows 上是 `C:\Users\<你的用户名>\AIExperts`，macOS / Linux 上是 `~/AIExperts`）。第一次打开面板能看到当前用的是哪个路径。


## 调用档位（默认自动）

`settings.json` 里 `mode` 三档，默认 **auto（自动识别并调用）**：

- `auto`：你说的话命中某位专家的触发词，插件就在这一轮开头插一句「先查专家库」，模型据此去查；
- `on-request`：只有你明确说「查一下阅读器专家」这类话才提醒；
- `off`：完全不提醒，资料库只供手动查阅。

**怎么避免刷屏**：关键词只从标题、`triggerWords`、描述、主题名里取，不从文件名/路径取；英文词至少 3 个字符且按词边界匹配，中文至少 2 个字。这样 `md`、`to` 这种碎片不会把无关问题（改脚本、跑 git）也判成领域问题。同一轮只提醒一次。

触发词来自专家的 `manifest.json`：`triggerWords`（具体问法，如 reader 的「行高 / 字号 / 段距」）+ 标题 / 主题名 / 描述。多条命中时按「命中次数多、词更长」决定归属，避免阅读器问题被界面专家抢走。

## 专家名规范

- **最多 5 个字，建议 4 个字**，两个字的自动补「专家」：`阅读器` → `阅读专家`；超 5 个字直接拒绝并给出建议。
- 名字要能一眼看出功能：生图专家 / 短剧专家 / 视觉设计专家 / 阅读器专家 / 插件开发专家。
- 面板上的名字用固定宽度胶囊（86px），四个字刚好，长短不一会参差。

## 技能名与简介的规范

每个专家对应一条技能，名字与简介由插件生成，不手写：

- **名字**：`expert-<专家 id>`，全小写 kebab-case，唯一。专家 id 只允许小写字母、数字、连字符。
- **简介**：`「<中文名>」资料库：<主题列表，最多 5 个>。用于：<什么时候用>。<N> 份资料，先查再答。`，上限 480 字符。
  - DSH 的技能目录只渲染 name + description，`whenToUse` 不会被单独显示——所以触发条件必须写进简介。
  - 主题列表来自 `manifest.topics[].title`，自动拼接；超过 5 个写「等」。
  - 「N 份资料」也来自 manifest，专家有多少料，目录里就能看出来。
- **自定义措辞**：总入口这类需要特殊说法的，在 `manifest.json` 里写 `"skillDescription": "..."`，优先生效。
- **想不出现在目录里**：`"expose": "none"`，只做资料目录，靠 `lookup_expert_knowledge` 找。

示例（自动生成）：

```
「AI 生图」资料库：结论速查、写提示词 / 负面词、角色一致性 / 锁脸、参数 / 工作流 / LoRA、出图界面 / 任务状态。
用于：用户要做 AI 生图、写/改提示词、选模型平台、查角色一致性或 LoRA 工作流资料时。22 份资料，先查再答。
```

## 装完就自带两个专家

插件包里带着两份通用资料，第一次启动会自动放进你的专家库（`<专家库根>/guide`、`<专家库根>/dsh-plugin`）：

- **专家库说明书**（`guide`）：一个专家目录该长什么样、三表怎么登记、什么时候该建新专家。
- **插件开发专家**（`dsh-plugin`）：插件最小结构、注入通道与工具注册、会话事件与后台任务、常见崩溃点。

规则三条：**只补缺**——你库里已经有同名专家就一个文件都不碰；**不覆盖**——你自己改过的内容永远保留；**可删**——不想要就删掉那个目录，下次启动也不会再塞回来。想强制重新放一份，把该专家目录删掉再重启即可。

## 建第一位专家

在对话里直接说：

> 帮我建一个「AI 生图」专家，把 `D:\调研\生图` 下这些资料整理进去。

模型会调 `expert_create` 生成骨架，再用 `expert_ingest` 把每份资料**搬进**专家库并登记。不需要你自己拼目录。

落下来是这样（资料本体在专家目录里，不在别处留副本）：

```
<DSH_EXPERT_ROOT>/
└── ai-image/
    ├── SKILL.md                 # 名称、简介、正文（模型真正读到的部分）
    ├── manifest.json            # 标题、状态、调研模式、主题与资料清单
    ├── references/              # 所有资料，按主题分节
    │   ├── index.md             # 资料索引（资料名 / 路径 / 一句话）
    │   ├── prompt-weighting_20261113/     # 一份资料一个英文目录
    │   └── ...
    ├── 资料对照.md              # 中文名 ↔ 英文目录
    ├── 资料快捷方式/            # 中文名 .lnk，双击直达英文目录
    └── survey.md                # 尽调计划 + 步骤 + 进度记录
```

**为什么目录名是英文**：中文目录在 PowerShell / MSYS / Python 之间来回搬时会被按错误编码读写，本机就出过一次乱码目录。中文名不丢——它写在 `manifest.json` 的 `title`、`references/index.md` 和 `资料对照.md` 里，面板也按中文显示。

`SKILL.md` 的 frontmatter 至少要有 `name` 和 `description`；正文控制在 8K 字符以内，细节放 `references/`。

## 把一段旧资料搬进来

```
expert_ingest({ expert: "ai-image", source: "D:\\调研\\生图\\提示词调研" })
```

- 只强制 `expert` 和 `source`，目录或单个文件都行；
- 资料会被**移动**到 `references/<英文目录>/`，原位置不再保留；留一张 `README.md` 说明搬到哪里，读到它的会话会被提示来查专家库；
- 标题、主题、一句话、什么时候用会从正文推断，推断出来的标「自动推断，可改」；想指定就传 `title` / `topic` / `slug`。

## 功能

| 能力 | 说明 |
| --- | --- |
| 专家即技能 | 每位专家注册成 `expert-<id>`，出现在模型可见的技能目录里，按需加载 |
| 尽调工作流 | 计划、按步记录、并行派子智能体、独立工作区，进度写回 `survey.md`，可随时续跑 |
| 说人话的面板 | 左栏「专家库」：这位专家会什么、按什么主题找资料、最近被哪个会话用过 |
| 成熟度标记 | 前四颗星只看资料本身（起步 / 可用 / 可靠 / 权威），第五颗星「标杆」才要求真的被用过；点开能看到「为什么是这个星级、怎么补」 |
| 主动调用 | 三档可切（见下「调用方式」）：自动识别 / 只在点名时查（默认） / 完全不主动调用 |
| 会话内徽标 | 模型加载专家技能或读资料时，对话里出现一行 `📚 专家：ai-image · 读 references/01-提示词.md（12K 字）` |
| 调用留痕 | `<根>/.trace/trace.jsonl` 记录每次 `skill_load` / `ref_read` / `write` / `plan` / `subagent` |

## 工具

| 工具 | 用途 |
| --- | --- |
| `expert_list` | 列出专家库现状 |
| `expert_create` | 新建专家骨架（不覆盖已有目录） |
| `expert_plan` | 写尽调计划：目标 + 步骤 + 模式（`parallel` / `serial` / `workspace`） |
| `expert_record` | 记录某一步的结论，可同时打勾 |
| `expert_dispatch` | 真并行派发：每个未完成步骤各建一个子会话跑，跑完自动记回 `survey.md`，再给一段合并去重 prompt（`run: false` 只出 prompt） |
| `expert_workspace` | 在专家目录下开独立工作区，直接建好会话、投递开场提示；这一轮结束时把 `workspace\out\*.md` 收成一条进度记录 |
| `expert_status` | 读当前状态：目标、步骤完成度、最近记录 |
| `expert_mode` | 只切模式，不动步骤与进度 |
| `expert_next` | 串行模式取下一步，附现成的子任务提示；`expert_record` 会拦住跳步（确要跳传 `force` 并写原因） |

| `expert_ingest` | 把手头一份资料（目录或文件）搬进专家库：只给路径即可，标题/主题/一句话会推断并标「自动推断」 |
| `lookup_expert_knowledge` | 按问题关键词查「该先读哪几份」，返回中文名、路径、所属技能；查不到返回 `missing` 并提醒先问用户 |

## 星级怎么算

五颗星，前四颗只看资料本身，第五颗才看有没有被用过。

| 星级 | 名字 | 意思 |
| --- | --- | --- |
| ★☆☆☆☆ | 起步 | 资料还薄，或者索引/说明没补齐 |
| ★★☆☆☆ | 可用 | 结构完整、覆盖够用，能拿来查了 |
| ★★★☆☆ | 可靠 | 主题分得匀、内容写得实，多数问题能查清 |
| ★★★★☆ | 权威 | 结构、覆盖、内容、新鲜度都到位，调研计划做完了 |
| ★★★★★ | 标杆 | 已经到权威，而且真的被用过（使用分 ≥ 50、至少 2 个会话） |

内容分由五个维度加权得出：

| 维度 | 权重 | 看什么 |
| --- | --- | --- |
| 结构完整度 | 0.25 | 文件在盘、进索引、索引有说明、中文名、桌面快捷方式，五项各占一部分 |
| 覆盖均衡 | 0.25 | 资料总量、主题分布是否均衡、平均每主题几份 |
| 内容可用度 | 0.20 | 文件是否够大、有没有来源链接、有没有写结论 |
| 新鲜度 | 0.15 | 按半衰期折算：生图 90 天，游戏/阅读器/插件 180 天，界面/短剧/播放器 365 天；若在 `manifest.json` 的 `reviews` 里写了复核日期，就按复核日期算 |
| 调研闭环 | 0.15 | 计划完成率、记录里有没有带数字的结论 |

使用分只影响最后一颗星：被几个会话用过、读到多深、读后有没有产出；占位加载不算。

面板里每位专家都有一栏「为什么是这个星级」：逐条写「资料齐不齐 / 主题分得匀不匀 / 写得实不实 / 新旧程度 / 调研做到哪一步 / 有没有人用过」，再写「离下一颗星还差什么」。

### 两个可选的小文件，能让它更准

- `references/queries.md`：写 8–12 条「用户会怎么问 → 该命中哪份 → 要点」，插件会自己跑一遍，告诉你「10 个常见问题里有几个能直接找到」。没有这个文件就不算这项，不扣分也不编造。
- `manifest.json` 的 `reviews`：形如 `{"references/prompt-basics": {"reviewedAt": "2026-11-16"}}`，记录某份资料哪天复核过；不写就按文件修改时间算新旧。

## 一份资料只有一个家

一份资料只写进一个专家的 `manifest.json` 的 `topics[].files`；别处要用，只写一行指针（带触发条件），文件本体不复制。
判断标准：把结论换到「某个 App」上仍然成立，就该归通用的 `ui-design`；必须靠这个产品的专有名词才说得清，归产品专家。

登记完跑一遍检查：

```bash
node scripts/check-ownership.mjs "<你的专家库根目录>"
```

它遍历每个 `manifest.json`，同一路径出现两次就报错（退出码 1）。

## 它查资料时什么时候停下来（设置 → 汇报节奏）

三档，默认第二档：

| 档位 | 什么时候停 | 适合 |
|---|---|---|
| 每查完一份就停 | 每份资料后用 3–5 句说清「学到什么、结论、想改的方向、启示」，等你回应 | 方向没把握、资料少、要逐份把关 |
| **只在需要转向时停**（默认） | 平时不停；只在① 新资料推翻原假设 ② 冒出更重要的新主题 ③ 连续 2 份没拿到有效结论 ④ 查到的与目标不符 时停下问 | 绝大多数情况 |
| 全部查完再汇报 | 中途不问，跑完一次性说结论、冲突、缺口 | 你在忙、方向已经清楚 |

不论哪档，每查完一份都会在 `survey.md` 的进度记录里留一句不超过 80 字的结论，面板的「最近发生的事」与时间线随时能看；你发消息就能打断它。

## 补资料要不要先问你（设置 → 补资料授权）

补资料会花额度、会往库里写文件，所以默认最保守：

| 口径 | 含义 |
|---|---|
| **每次问我**（默认） | 查到库里没有，先停下问「要不要补」，你说「补」才动 |
| **提前授权，按步数跑** | 事先授权，按设定步数自己跑（1/2/3/5 步），跑完汇报 |
| **只对指定专家放行** | 白名单里的专家自己补，其余仍然每次问 |

三档都只授权「按计划表补资料」，**不授权新建专家**。设置存在库根的 `settings.json`（`fillMode` / `fillSteps` / `fillExperts`），跟着专家库走。

## 查不到时按「检索模式」交回流程

`lookup_expert_knowledge` / `expert_find` 返回 `missing: true` 时，提示不是一句「要不要新建专家」，而是按这位专家当前的模式给出可执行动作：

- **serial（本会话串行）**：调 `expert_next` 取下一步 → 在本会话查 → 结论写成 `references/` 下文件 → `expert_record` 写回 survey。提示里明确写「不要手写资料目录、也不要派子智能体」。
- **parallel**：`expert_dispatch` 派子会话并行查，结论 `expert_record` 回填。
- **workspace**：`expert_workspace` 开独立工作区，收尾回填。

模式以该专家 `survey.md` 头部为准；若与设置里的全局 `research` 不一致，提示会把两种口径都写出来（并给出 `expert_mode` 的调整建议），避免「改了设置却没反应」。`expert_create` 只在「完全不属于任何现有专家职责 + 用户明确同意」时提。

## 调用方式与调研方式

面板右上角齿轮进设置页，两组选择都写进库根 `settings.json`，改完立即生效。

**调用方式**（`mode` 字段）：

| 档位 | `mode` | 行为 |
| --- | --- | --- |
| 自动识别 | `auto` | 这句像某位专家的领域就在回合开头提醒一次；查过就不再提醒 |
| 点名才查 | `on-request` | **默认**。只有你说「调用 / 问问 / 请教 / 查阅某专家或某资料库」时才提醒；其余输入完全不碰 |
| 不主动调用 | `off` | 任何输入都不提醒、系统提示里也不出现这条规则；专家库只是个静态资料库，`expert_create/plan/dispatch/ingest` 这些建库工具照常可用 |

**调研方式**（`research` 字段）：

| 方式 | `research` | 行为 |
| --- | --- | --- |
| 并行 | `parallel` | `expert_dispatch` 给每个未完成步骤各开一个子会话同时查，结果自动回写，再给一段合并去重 prompt |
| 串行 | `serial` | **默认**。用 `expert_next` 取下一步，查完 `expert_record` 记结论再取下一步；这一档**不开任何新会话**（`expert_dispatch` 会直接拒绝并让你用 `expert_next`）；`expert_record` 会拦住跳步（确要跳传 `force` 并写原因） |
| 独立工作区 | `workspace` | **暂停使用**（选项置灰、写入会被拒）。做法是「一个专家一个固定房间」：会话号写死为 `session-expert-<专家>-workspace`，目录固定为 `<库根>\<专家>\workspace\`，多轮调研都在同一个会话与目录里累积；活的直接续、重启过用 `agents.resume` 按同一号码接回，接不回才新建。测试期可用 `DSH_EXPERT_ENABLE_WORKSPACE=1` 临时打开 |

也可以直接改文件：

```json
{ "mode": "on-request", "research": "serial" }
```

插件自己开的派发子会话与工作区会话只用来造资料：它们会并进发起它们的那个会话里显示，但**不算「用过的专家」**，也不进使用统计。

## 配置

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `DSH_EXPERT_ROOT` | 插件内置默认目录 | 专家库根目录：每位专家一个子目录，资料放进该专家的 `references/` |

## 它是怎么工作的

- 宿主侧通过 `ctx.skills.registerProvider()` 把专家库接进技能系统：`list()` 只返回名称和简介，`get()` 才读 `SKILL.md` 正文，所以没被点名的专家不占上下文。
- `ctx.tools.register()` 注册上表 12 个工具，写盘后让技能缓存失效，新专家立刻可见。
- 监听 `agent/pre-step`：按 `settings.json` 的 `mode` 决定——`auto` 用主题词命中、`on-request` 只认「调用 / 问问 / 查阅 + 专家或资料库」的明确指令、`off` 直接返回。命中后在本步消息末尾插一行「先查资料库」，同一回合只提醒一次，查过的回合不再提醒。不再用 `agent/turn-stopping` 硬拽模型。
- `ctx.systemPrompt.section()` 注入的规则文本跟着 `mode` 走：`auto` 允许自己判断，`on-request` 写明「用户没点名就别查」，`off` 返回空字符串（等于不注入）。
- 监听 `tools/post-execute`：加载专家技能、读专家目录里的文件、派子智能体，都写进 trace，并在下一轮回复里插一行徽标。
- 面板和 trace 通过 5 个只允许本机访问的 HTTP 路由读取，路径校验拒绝越界访问。

## 面板里能看到什么

左栏「专家库」三个页签：

- **概况**：一句话总结（「最近 30 天，模型读了 33 次资料」）、4 个关键数字、30 天读取柱状、8 周×7 天活跃热力、五位专家的阶段分布、读得最多的 5 份资料、最近 5 件事。
- **资料**：每位专家一张卡片（星级、主题数、资料数、上次被用），点开按主题列出「你要做什么 → 该读哪几份」，再下面是全部文件与技能说明。
- **调用记录**：按会话分块，每块写「用到的专家：AI 生图 ×3、界面与交互 ×1」；顶部下拉可只看某个会话或「本机脚本写入」；子会话不单列，行内第二行标「子会话 · 派发任务名」。

## 常见问题

**装完为什么没出现「专家库」？** 安装改了 bundle 组合，必须重启一次 DSH。之后改插件代码不用重启——宿主侧走 hmr 热替换，浏览器侧刷新页面即可。

**为什么我新建的会话在调用记录里只显示「未命名会话」？** 面板按 5 秒轮询读会话文件；新会话的标题还没落盘时先显示占位，刷新后会换过来。

**星级升不上去怎么办？** 打开该专家卡片看「为什么是这个星级」，逐维写了差什么：「资料齐不齐」「主题匀不匀」「写得实不实」「新旧程度」「调研做到哪一步」「有没有人用过」，以及离下一档差多少。

## 局限

- 模型会不会主动加载专家，取决于 `description`、`when-to-use` 和注入的规则；写得太泛仍可能被通用技能抢走。
- 成熟度里的「真实使用」只看本机 trace；换机器或清空 `.trace` 后会重新从 0 累积。
- 面板轮询 5 秒一次，不推送；调用记录要刷新才更新。
- 只监听 `DSH_EXPERT_ROOT` 下的目录，不做向量检索。

## 清单校验、自测覆盖、旧资料标记

三件事都不拦人，只把问题摆出来：

- **清单校验**：清单里写了但磁盘上没有、磁盘上有但清单没登记、库外链接失效、空文件，都会在「这里有什么资料」里列一行。
- **自测覆盖**：`references/queries.md` 里每个主题至少该有一条问题；某个主题一条都没有，会在自测行写「覆盖 3/7 个主题（缺：…）」。
- **答不答得上**：命中了资料但正文里没有可执行结论（数字、命令、约束词、明确结论）的，算「答不上」，单独列出来。
- **旧资料**：超过 365 天没复核的，列一份「该复核」清单。

## 资料缺口提醒

「这个库到底答不答得上现在的问题」由两个信号算：`references/queries.md` 的自测命中率，加上运行时 `expert_find` / `lookup_expert_knowledge` 查空的次数。缺口超过阈值（默认 20%，设置页可改 10/20/30/50%）时，回复末尾会插一句提示，一位专家 24 小时最多提一次；该提示由插件写入，不额外消耗调用。

**首页也能看到**：概况页有一块「需要补的资料」，列出答不上来的专家、次数与最近没查到的问题，点名字直接跳到该专家。会话里那句提示只是提醒，清单以面板为准。

## 面板上的小改进

- 页签带数量（专家 8）；「刷新」左边常驻「更新于 13:51」，滚到哪都知道数据多旧。
- 出错时错误条后面直接跟「重试」，原始报错收进「技术细节」。
- 调用记录顶部有搜索框，可搜会话名、专家名、资料名。
- 专家详情加「调研进度」：只摆正在做的那一步，做完的折进「已完成 N 步」。
- 派发调研时卡片上显示「已跑 1 分 47 秒」。
- 概况页「需要补的资料」：答不上的专家、次数与最近没查到的问题都摆出来，不用靠会话转述。

## 资料放在哪、会往外发什么

- 默认位置是 DSH 数据目录下的 `expert-role/experts`；可以在「设置 → 资料目录」换到任意盘，旧目录不删，也可以整体迁走。
- 检索默认在本机算：资料不出这台机器。只有你自己在设置里填了外部 embedding 服务，才会联网。
- 插件不收集任何统计信息，不联网上报。
